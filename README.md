# صحتك فلاحي — واجهة ويب مرتبطة بمشروع Supabase الحالي

هذه واجهة عربية RTL تستخدم جداول مشروعك الموجودة: `employees`, `reports`, `complaints`, `branches`. لا تنشئ جداول جديدة ولا تغيّر السياسات الحالية.

## 1) إعداد مفتاح الاتصال
افتح `config.js` وضع قيمة الـ **Publishable Key** مكان `PASTE_YOUR_SB_PUBLISHABLE_KEY_HERE`. رابط المشروع موجود مسبقًا. لا تستخدم `service_role` أو أي `secret key` في ملفات المتصفح.

## 2) إعداد حسابات الدخول
تسجيل الدخول بالكود في الواجهة يحوّل كود الموظف `1025` إلى البريد الاصطناعي `1025@sehatak-fallahy.local`. لذلك يجب إنشاء مستخدم Auth لكل موظف بالبريد بهذا النمط وكلمة مرور يحددها المسؤول، ثم ربط UUID الخاص به بسجل الموظف في `employees.auth_user_id`.

**لا تنشئ حسابات أو تغيّر أدوارًا عبر الواجهة العامة.** أنشئ المستخدمين من Supabase Dashboard > Authentication > Users، ثم اربط `auth_user_id` من بيئة إدارية موثوقة. إذا كان تأكيد البريد مفعّلًا، أكّد الحسابات إداريًا؛ البريد `.local` ليس صندوق بريد حقيقيًا.

## 3) تشغيل محلي
يمكن فتح `index.html` في المتصفح أو تشغيل خادم ملفات من مجلد المشروع:

```bash
python -m http.server 8080
```
ثم افتح `http://localhost:8080`.

## 4) ما يعمل في هذه النسخة
- تسجيل الدخول عبر Supabase Auth (بعد إنشاء حساب Auth وربطه بسجل الموظف).
- عرض ملخص الموظف وعدّاداته.
- إنشاء تقارير يومية وحفظ المهام كـ JSONB في `reports.tasks`.
- إنشاء الشكاوى وعرضها وتحديث حالتها للإدارة وفق RLS الحالي.
- لوحة إدارة وتقارير موظفين مبنية على الجداول الموجودة.

## ملاحظات مهمة
- لا يمكنني الاتصال بحساب Supabase الخاص بك أو نشر التطبيق نيابةً عنك من هذه المحادثة؛ يلزم تشغيله واختباره داخل حسابك.
- رفع ملفات الصور لم يُفعّل بعد؛ حقل `attachment_paths` موجود لكن يلزم إعداد Storage وسياساته.
- قبل الاستخدام الفعلي، اختبر RLS بحساب موظف وحساب إدارة منفصلين. يجب أن يكون `employees.auth_user_id` مضبوطًا، و`role='admin'` و`active=true` لحساب الإدارة حتى تعمل `is_admin()`.
- لا تشغّل مخطط `schema.sql` القديم على مشروعك الحالي؛ هذا المشروع يستخدم الجداول التي فحصناها ولا يحتاج إلى تكرارها.
